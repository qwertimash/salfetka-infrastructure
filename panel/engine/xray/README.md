# Managed Xray runtime — B4 development

Server-only dependency, generated by `python3 panel/scripts/prepare-xray-server.py`
from verified local pins. Authoritative changes are the locked patch in
`panel/third_party/patches/xray-server`; never edit the mobile dependency to build it.
The nested module keeps Xray out of the control-plane API/worker dependency graph.

The typed runtime accepts only VLESS RAW/TLS with per-grant UUIDs; no API listener,
free-form Xray JSON, mux, reverse or fallback is configured. TLS certificate/key
come from the owning installation. Inbound admission and connection tracking share
a validator lock. Removal denies first, then closes only that incarnation's sessions;
a late cleanup cannot close a replacement user's sessions.

`Runtime` is an internal effect adapter, NOT an authentication boundary. Production
callers must use `internal/nodevpn.Controller`: verify a bounded signed complete
policy, bind node/installation/config/signer, persist generation before Apply, and
close the owned engine after ambiguous persistence. Every engine creation gets a
fresh random epoch; a prior signed policy cannot revive a restarted engine. A new
policy must bind this epoch and advance the durable generation. The panel delivery
path and product CLI are not connected yet; this directory is not an install recipe.

Per-grant leases are limited to5 minutes and checked by an independent runtime
watchdog. Higher-generation extension of the same credential preserves active flows;
expiry/rotation/deny closes TCP and UDP. Clock rollback closes grants and cannot be
cleared by merely correcting the time. These are bounded local clock protections,
not secure hardware time. Offline panel/agent process integration remains open.

Usage uses opaque grant IDs and a fresh engine epoch. Polling never resets counters;
nil counters mean not observed. This is not the durable B9 ledger or hard quota.

## Tests

From this directory, with the pinned wrapper:

```sh
GOWORK=off GOPROXY=off GOSUMDB=off GOMAXPROCS=4 \
  ../../../mobile/scripts/go.sh test -mod=readonly -race -count=1 -p 1 -timeout=120s ./...
```

`panel/scripts/check-b4.sh` also runs existing panel acceptance (requires its isolated
PostgreSQL URL). Loopback fixtures use real TLS, Xray clients, TCP/UDP echo and actual
counters. B0 negative receipts remain unchanged. The current clients use unchanged
outbound code from the same verified pin; no physical mobile acceptance is implied.
Linux arm64 functional tests run in an owned VM; the native macOS suite uses race.
